# CalDock Accounts, Orders and Referrals Implementation Plan

**Goal:** Add Google/Apple account entry, customer orders, affiliate links and a protected order administration area, using the user's existing craftos.app backend.

**Architecture:** Keep GitHub Pages as the public marketing preview. Serve the same CalDock bundle at craftos.app/caldock/ so account and payment flows share an origin with /api/caldock. Extend the existing Fastify/PostgreSQL service using separate caldock_* tables, identities, cookies, roles and audit records. Work OS/DingTalk identities cannot authorize CalDock or vice versa.

**Tech Stack:** Existing React/Vite frontend, Fastify, PostgreSQL/PGlite, jose OIDC verification. No Supabase migration or new paid hosting.

## Confirmed decisions
- Preserve the selected California Afterglow brand, Chinese/English and USD 199/month or 1799/year.
- Google or Apple federation; no passwords or simulated provider success.
- Affiliate: personal links, source/order attribution, administrator-configured commission rate, no automatic payouts.
- Conservative defaults: commission rate zero until configured, commission on first paid order by default, optional every-order mode; snapshot rate on order creation. No commission from signup or unpaid orders.
- Actual payment provider remains unconfigured. Orders can be created as pending; only verified server payment events can mark paid and accrue commissions.
- Explicit interactive demo uses fictional browser data and never writes to the production API; production auth never accepts demo identities.

## Tasks
1. Add isolated database schema, server-authoritative order pricing, idempotency, ownership and admin authorization. Test with PGlite and existing PostgreSQL CI adapter.
2. Add Google/Apple OIDC start/callback using state, browser binding, nonce, Google PKCE and verified JWT signatures/issuer/audience/expiry. Separate HttpOnly sessions, CSRF checks and exact-origin writes; no automatic email-based linking or first-user admin.
3. Add referrals, first-touch binding, commission settings/snapshots, verified payment event processing, refund voiding and audited manual settlement recording.
4. Add React login/customer/affiliate/admin pages in the existing warm style, search/filter, order detail, status update, commission settings and copyable link; wire checkout to pending order creation with idempotency.
5. Add production-safe frontend routing to craftos.app/caldock, local API proxy and Docker/Caddy packaging of a pinned frontend build without changing Work OS/Wiki routes.
6. Run auth/permission/tampering/idempotency/refund tests, backend typecheck and existing regressions; browser-test desktop/mobile, both languages and demo flow; build/test hosting contracts.
7. Publish frontend and backend only after checks pass. Verify GitHub and craftos URLs and capabilities. Report provider configuration as pending until real Google/Apple sign-in is verified.

## Production activation gaps
